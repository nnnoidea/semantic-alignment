# 语义检查

## 目的

帮助用户发现 Agent 在实现过程中是否偏离要求、补足了哪些用户未明说的选择；核对要求兑现，并交付可查证的检查结果。

## 限制

本主题比较用户语义与真实产物，不承担普通代码审查。可视化属于检查结果的呈现与交付，不是独立功能模块或任务入口；不提供实现前推演。以当前阶段约定、完成条件和适用限制核对本阶段；明确留到后续的最终目标保留为后续范围。未指定不等于错误、用户禁止或删除授权。

用户语义、Agent 组织或推断、真实实现和证据保持不同身份。图只呈现有依据的关系，不把尚未选择的办法画成实际流程。图和渲染输入不是新的语义基线、对象账本或覆盖缓存。

## 用户约定

### 要求与产物双向对照

**最终期望：** 找出所有与用户语义不一致的地方，包括遗漏、偏离和用户未提到的内容。

**当前阶段约定：** 逐项核对当前约定正文中的行为、条件、例外及适用的上层限制，完成条件作为补充；同时从真实产物独立反查要求之外的行为。覆盖当前范围内入口、分支、配置、辅助组件、依赖默认值、失败恢复、部分副作用和随包提供的未启用机制。

必须展示实际怎样落地，以及未实现、未核实的部分。语义记录的当前阶段约定不是实际实现；代码、测试和 Agent 自述也不是用户接受或决策理由的证明，来源不明时说明未知。

**本阶段完成条件：** 用户要求的兑现情况和未约定实现均能查阅；未检查区域明确保留，不据局部核对声称完整。

**关联约定：** 由[语义检查入口](activation.md#语义检查入口)确定本次检查任务；把反查出的未指定内容交给[全部选择披露](#全部选择披露)；把发现和证据交给[结果呈现与交付](#结果呈现与交付)。

**关联文件：** [audit-presentation.md](../../../references/audit-presentation.md)：双向核查、选择披露、修复信息和交付规则；[SKILL.md](../../../SKILL.md)：任务入口、语义检查边界和记录格式说明。

### 全部选择披露

**最终期望：** 用户能够看到 Agent 真实决定了什么，不仅是几个显眼例子。

**当前阶段约定：** 披露每个具体规则、取值、条件、先后顺序、输出和副作用，包含默认值、存储与数据流、算法、依赖、内部结构、触发、失败处理、界面文案、样式与交互。必要、合理、惯常、继承而来或影响很小，都不能成为隐藏理由。

例如只要求“文件复制器”时，覆盖、递归、链接、元数据、并发、校验和半途失败处理仍是未约定内容。按主题分组可合并重复说明，但须保留各自条件与后果；简洁不缩小发现与披露范围。

核对真实产物中的选择在报告中的落点，修正概括压掉的细节及同类遗漏；摘要、详情和附录保持一致。继承行为查明或标明未核实，“只读”等名称不证明无副作用，验证结果不证明决定来源。临时笔记按需使用，不转为常驻语义账本。

**本阶段完成条件：** 全部已检查选择及未完成范围均可追溯；完整性不能由已读文件数、缺陷数或措辞自信证明。

**关联约定：** 细化[要求与产物双向对照](#要求与产物双向对照)中对实现选择的核查范围；向[结果呈现与交付](#结果呈现与交付)提供每项选择、条件和后果。

**关联文件：** [audit-presentation.md](../../../references/audit-presentation.md)：双向核查、选择披露、修复信息和交付规则；[view-content.md](../../../references/view-content.md)：报告内容、语义来源与记录到图的含义对应。

### 可省附加机制

**最终期望：** 优先让用户看见没有细说、整层不加也不影响所需能力的机制及其代价。

**当前阶段约定：** 有证据时突出可省附加层，说明去掉后仍能做什么、失去什么、移除边界、前提、兼容牵连和资源影响；其他默认值及必须选一种的实现仍完整披露。

检查真实生产方、消费者和失败路径，区分移除机制与另选替代方案。SHA-256 是示例而非可删规则：可能是附加检测，也可能承担用户要求的来源身份。正常输入对照成功不足以证明所有场景无影响，不虚构收益、节省量或必要性评分；探索原型不等于可交付变更。

**本阶段完成条件：** 用户可据保留能力、损失及未知后果判断取舍；证据不足时不确信推荐删除。

**关联约定：** 从[全部选择披露](#全部选择披露)的选择中识别可整层省去的候选；向[修复确认](#修复确认)提供移除边界及未定后果。

**关联文件：** [audit-presentation.md](../../../references/audit-presentation.md)：双向核查、选择披露、修复信息和交付规则。

### 修复确认

**最终期望：** 检查后说明修复需要哪些信息、其中哪些真正需要用户决定。

**当前阶段约定：** 先复用用户已有意图、回答和授权，并调查可查事实；只询问影响修复目标、范围、完成要求或重要后果的未定事项。说明不确定性、具体问题、可比较方案、不同答案的影响和依赖工作，有依据时给建议。

恢复明确要求及普通实现判断不增加统一审批；无新增确认点时简短说明。未约定内容不会因无需询问而从报告中消失，也不会自动获得删除授权。

即使只要求检查，也应给出这项判断。等待必要回答时继续已授权且独立的工作，只暂停依赖答案的部分；已有授权不重复询问。确需额外授权时先完成可做的准备，确认后将被接受的长期决定写回语义。

**本阶段完成条件：** 修复所需的真正未定信息和决策明确，用户可判断具体选项；没有新增确认点时如实说明。

**关联约定：** 把用户接受的修复约定交给[当前含义更新](records.md#当前含义更新)保存；向[结果呈现与交付](#结果呈现与交付)提供真正需要决定的问题及其影响。

**关联文件：** [audit-presentation.md](../../../references/audit-presentation.md)：双向核查、选择披露、修复信息和交付规则。

### 结果呈现与交付

**最终期望：** 用户先看清检查发现的整体关系，再逐层理解真实做法、未指定选择及其影响；完整要求、细节和来源可查，呈现模板可供不同项目复用。

**当前阶段约定：** 可视化是语义检查结果的输出方式，以已核查的发现和证据组织报告，继承该次检查的范围与验证局限。

明确要求语义检查时，默认提供本地交互 HTML／SVG 及可编辑检查 Markdown，用户指定其他格式时遵循。可视化为主要阅读入口，Markdown 按约定及其实际实现关系组织完整发现与证据，服务图、详情和原文查阅，不单独规定长报告的线性阅读顺序。

用户补充：“我感觉还需要一个汇总页面，毕竟用户也可能懒得仔细看，只想看看汇总后的不一致，这个得单独加”。另外提供独立的差异汇总页面，便于用户快速查看检查发现。

用户补充：“需要突出显示跟‘限制’相违背的差异，因为这是用户最关心的”。优先突出已经确认违背用户限制的差异，并保留对应的限制、实际做法和来源；未指定内容仍按原约定披露，不自动等于违反限制。

默认阅读路径为“用户约定 → 对应的实际流程 → 关键步骤、选择与证据”；共同范围、结论、验证局限集中说明，附录、已检查及未检查范围和复用证据日期均可查阅。全部实现组及未约定选择保留，不能只选重要例子；完整内容也应适于阅读和打印。

只有有用且目标存在时才链接其他视图。来源、用户阶段约定与真实实现保持不同身份，未指定实现不因放进要求框而成为用户同意的内容。更改呈现不代表重新验证底层产品。

#### 范围与内容

检查报告在本次检查范围内选择项目总览、单模块或多模块模式。项目总览粗略展示边界和主关系；单模块展示内部职责、过程、分支和选择；多模块展示主要交互及相关内部过程。通常聚焦最新修改模块，同时保留理解所需上下文；范围确实不明时才询问，不自动生成所有模式或组合。检查范围与阅读入口分开：范围内默认按相关约定进入，用户明确要求架构／流程总览时可从该视图进入，约定仍是判断依据。

以用户语义为骨架，互补要求同层关联，细化或归属用嵌套表达。大框与同层节点之间应有明确的过程、信息或约束关系，保留操作、判断、等待恢复、输入输出、返回及相关异常，不能只堆卡片或把清单连成流程。非执行规则画关系，不暗示自动状态机或工具执行顺序。

图上标题、节点、关系标签和详情中的用户要求，均遵循项目共同限制中的原话规则；过长时稍微压缩，详情或来源保留完整措辞。原话不可得时引用连续语义记录原文，说明出处；Agent 整理的分组、缩写和实现观察保留各自身份、条件与例外。共享实现保留一个主要说明，相关约定精确链接到对应步骤，并可返回；不为不同约定重复整章实现。未实现要求和无明确用户要求的配套实现都保留。

最终期望与当前阶段约定均进入“用户要求”，真实实现须另行核查。已明确延期的功能显示为后续范围；关联文件仅用于定位。缺少语义内容仍显示缺少，未核查、未核实和未约定分别表达。

#### 层级展开

最多三层：用户约定、对应的实际流程、按需关键步骤；简单内容可以更早结束，具体参数与证据进入末端详情。每张局部图保持简洁，重要完成条件、等待、返回和失败仍可见，完整内容不因简化而丢失。

初始只显示主图；选中约定或步骤后在下方展开，保留祖先图和选中状态。每层保留一条分支，切换上层时替换后代。末端节点与关系显示详情，父节点自己的说明和来源仍可折叠查阅。

子图外框对应整个父节点职责，说明本层从上层哪里进入、携带什么输入，结果或影响接回哪里；用必要的上层引用和边界连接表达，不重画整个上层，也不虚构执行步骤。上下层输入输出与完成条件一致，区分返回、异步影响和完成；对应关系不明时明确缺少。

#### 详情与状态

汇总页和节点详情采用用户认可的读法：“具体发现 → 简短对照 → 按需查看证据”。每项发现先用一句用户立即能理解的具体事实做标题；违反限制／要求未兑现给出用户要求与真实做法的简短对照，Agent自行补充直接列出具体决定，点开再看影响；尚未核实单独标明。颜色用于强调已有结论，不能代替说明差异。

作用、长原文、来源、详细取舍及完整“用户要求、实际做法、影响与取舍”保留在展开内容中，作用仍须具体。适合关系、分支或映射的内容保留简单小图，节点和关系可点开说明；没有可表达关系时不制造流程。小图属于末端详情，不继续递归展开。

用户补充：“用户要求、实际做法，这两点内的文字能否通过颜色来表示是哪部分做的跟用户要求的不一样、不一样的点在哪”。文字标色应能让用户看出具体哪部分不同、不同在哪里。

用户未指定的具体选择直接标在实际步骤或关系上，并保留影响和约定边界；不设独立“用户未指定”字段，也不要求用户自行推断全部差异。“对齐情况”“待用户决定”“是否询问／下一步”不作为固定详情字段，总体检查结论和修复问题留在报告中；具体发现直接呈现。

节点和关系的用户要求引用约定，实际观察放在实际做法中。要求明确但行为未验证时，实际做法注明未核实，不改写成约定尚未核查。打开详情前就应区分已发现的未指定选择、尚未核查及方案未定；Agent 已选择实现不消除未指定状态。缺资料不证明用户没说，标记不表示实现通过或用户认可。父模块提示下层状态，已识别数量与未核查范围分别表达，不能误导为每个子项都同样缺少。

完整原文、具体取值、条件、出处和上下文保持可达；未知实现写未核实，作用或影响无资料时明确缺少。图例解释所有实际使用的颜色、线型、形状和交互标识，在 HTML 与独立 SVG 中完整提供。

#### 模板与浏览

提供原生 SVG、HTML 骨架、样式、交互、常见流程布局和统一生成／检查入口。各项目提供自己的内容、关系、来源和父子交接，不照搬示例的模块数量；模板负责绘制与常见布局，特殊位置可以局部调整，不承诺所有复杂图都自动美观。

查看器保留图的放大缩小、原生上下滚动、放大后的横向滚动、拖动、节点和关系选择及关闭详情；主界面简洁，不再提供定位下拉、搜索、定位匹配、适合宽度／全图、独立窗口、下载工具栏和缩放百分比。完整原文入口继续保留，来源路径可读。

用户反馈：“每次点击节点，画面跳转太突兀了”；需要改善点击后的跳转体验。

用户反馈：“这个按钮太小太偏了，很容易被忽略”；报告中的关键入口应醒目、便于发现。

仅保留当前分层可视化生成链路和填写示例，删除旧版平面图、表格输出及其兼容逻辑；当前链路使用的共享组件保留。已生成的报告保留其当时身份，不自动当作当前设计。

生成产物自包含，不新增 MCP 或常驻服务。保留实际输出的链接、详情、展开路径及明显布局问题检查；删除开发回归脚本、内嵌自测和模拟 DOM 测试。输出检查不等于语义完整性、真实浏览器效果或真实产品验收。

**本阶段完成条件：** 检查发现、图、详情和完整原文互相对应；整体关系、父子交接及语义状态清楚，全部已核查内容与验证局限可访问。检查失败后应保留哪些输出尚未约定，不虚构发布保证。

**关联约定：** 接收[要求与产物双向对照](#要求与产物双向对照)的发现；接收[全部选择披露](#全部选择披露)的完整选择明细；接收[修复确认](#修复确认)的决策信息；依据[记录结构与文件组织](records.md#记录结构与文件组织)引用用户语义并保留阶段区别；使用[说明与版本](packaging.md#说明与版本)维护的模板与工具。
