# Skill 说明与交付

## 目的

让 Agent 以简短、职责明确的说明使用现有能力，让用户方便审阅当前约定。

## 限制

项目语义与开发维护资料存放在安装包之外并予以保留。说明中只保留影响判断、操作或本 Skill 特有边界的内容，删去通用常识、重复论证、冗长例子及已被当前规则覆盖的历史禁令。

## 用户约定

### 说明与版本

**最终期望：** Skill 的说明与模板容易理解、可复用，用户能审阅其含义。

**当前阶段约定：** 能一句话说清的规则用一句话。入口围绕语义检查及其记录依据组织；检查说明负责核查与结果交付，报告内容与来源、报告模板使用两份说明辅助交付。规则在负责位置定义，其余引用。

README 也应服务于本项目的设计目的，并考虑哪些用户真正需要它。用户原话：“需要满足我们的设计目的，想想会有哪些用户需要这个”。 README 要有吸引力，用户要求：“开头两句要直击问题，然后简单说我们怎么解决，然后要附图”。

仅本项目的语义记录和语义检查结果可以上传，作为结果展示；README 应邀请其他人查看最终得到的内容，并附上截图。可行时，语义记录默认不随下载提供。这是本项目的公开展示约定，不扩展为其他项目的上传授权。

模板说明只解释选择模板、输入字段及其含义、生成和检查。颜色、线型、尺寸、布局和交互由现有模板提供，不另写一套手工绘图规范或完整底层 API 清单；需要例外调整时按需查阅实现。

仅保留英文正式来源和安装版本，修改后同步安装副本。安装包只保留当前出图链路、必要输出检查和模板填写示例，删除旧版兼容及开发测试。

停用 TaskMemory MCP，日常语义维护使用文件，不恢复旧工具或新增常驻服务。说明精简保留完整披露、来源区分、从产物反查与当前语义一致性。

**本阶段完成条件：** 各份说明职责明确且无重复定义，英文正式来源与安装副本一致；语义记录独立保留。

**关联约定：** 依[记录结构与文件组织](records.md#记录结构与文件组织)保留独立项目记录；为[结果呈现与交付](audit.md#结果呈现与交付)提供当前模板、说明及工具；在说明精简时保留[全部选择披露](audit.md#全部选择披露)的范围与来源要求。
