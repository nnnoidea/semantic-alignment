日期：2026-11-09。

## 约定未核查与实现未核实分别呈现

用户当前约定：“缺少语义内容仍显示缺少，未核查、未核实和未约定分别表达。” 来源：本项目 semantics/audit.md。

实际做法：summary_findings 将用户约定范围尚未调查生成内部 unreviewed 发现；共用渲染显示“约定未核查”。缺少实际做法或简图说明仍独立生成 unverified，显示“实现未核实”。两种缺口可并存。不会只因约定范围未核查，就判定实现未核实。

具体实现选择：使用内部 unreviewed 类型，作者 comparisons 仍只接受原来的五类；新增分区有内容才显示，沿用灰色标签。完整正文、三字段与证据保持可达。这些是 Agent 选择的落地方法，不是用户规定的数据枚举或颜色。

## 摘要保留待定状态及其范围

用户当前约定：“打开详情前就应区分已发现的未指定选择、尚未核查及方案未定。” 来源同上。

实际做法：本项 pending=true 时摘要组显示“方案待定”；仅内部简图含 pending 时组显示“含待定方案”。小图节点与关系各自把待定标记带到自己的发现，其他兄弟选择保持原状态。没有其他发现的待定项也进入摘要，不因省略 match 而消失。

具体实现选择：没有其他发现时使用内部 pending 发现单列；已有发现时保留组或对应小图项的状态，不为每条普通选择复制待定。紫色沿用图的待定配色；“其他待定方案”仅统计单列条目，不能读成全部待定数。未恢复实现前推演，也未增加“待用户决定”字段。

### 共享实现导航的现有做法

- `semantic_template.py:detail_html` 接收 links=[{target,label}]，文本和目标转义后写成 detail-reference 锚点；字段由报告作者填写，不推断哪个实现属于哪条约定。
- `layers.py:prepare_details` 在生成期间建立详情正文、标题和引用的内存映射；先限定本层键，再找显式链接。用生成 HTML 的固定标签匹配，不解析用户语义。相同目标按字典键去重；不会凭空生成不存在的目标。对象引用自动补“返回：来源标题”；已有显式反向链接或自引用不重复补。多个约定引用同一步时，每个入口各有一个返回链接；不根据用户点击历史只保留最新来源。
- 同一项的正文仍可能保留作者重复填写的正向链接；生成器只避免重复自动返回。目标是全文锚点时不补返回。合格项的导航也复制到完整阅读内容中；调用既有 hash 导航展开祖先，没有新增浏览器状态存储或语义账本。
- `check_report.py:Index/check_report` 收集详情内锚点，对显式引用的对象目标核对反向可达；检查不判断“关联是否真的合理”，也不要求任意手写 HTML 链接都有反向跳转。缺目标、缺返回会报错，但仍遵循先写文件再检查的既有输出顺序。
